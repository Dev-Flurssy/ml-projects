CATEGORICAL DATA

Categorical data is a type of qualitative data that groups information into distinct categories based on shared characteristics.
Instead of representing information with numbers, it uses labels or names to describe different groups.
Examples include gender, nationality, blood group, education level, and customer satisfaction ratings.

------------------------------------------------------------
ENCODING CATEGORICAL DATA

Encoding is the process of converting categorical data into numerical vectors that a machine-learning model can train on.
Models can only work with numbers and floating-point values. 

They cannot directly understand text values such as:
- "Dog"
- "Maple"
- "Red"
- "London"

Therefore, categorical values must be transformed into numeric representations before they become part of a feature vector.

------------------------------------------------------------
DIMENSION OF A FEATURE VECTOR

The term dimension refers to the number of elements contained in a feature vector.

Examples:
Feature            Categories
Snowed Today       2
Skill Level        3
Season             4
Day of Week        7
Planet             8

Features with only a small number of possible categories are called low-cardinality features.

------------------------------------------------------------
VOCABULARY ENCODING

For low-cardinality categorical features, each possible category is added to a vocabulary.
A vocabulary is simply the complete list of valid category values.

Example:
Car Color Vocabulary
- Red
- Orange
- Blue
- Yellow
- Green
- Black
- Purple
- Brown

Each category is then assigned a unique index number.
Red     → 0
Orange  → 1
Blue    → 2
Yellow  → 3
Green   → 4
Black   → 5
Purple  → 6
Brown   → 7

------------------------------------------------------------

WHY INDEX NUMBERS ARE NOT ENOUGH

Suppose we keep only the index values:
Red     → 0
Orange  → 1
Blue    → 2
Purple  → 6

The model may incorrectly assume:
Purple > Blue > Orange > Red
or even believe Purple is six times larger than Red.

This relationship does not actually exist.
The numbers are merely identifiers.
Because of this problem, categorical features usually require One-Hot Encoding.

------------------------------------------------------------
FROM A CATEGORY TO A FEATURE VECTOR
Take one car from the dataset:
- Color = Blue

The model converts this into: [0, 0, 1, 0, 0, 0, 0, 0]

The model never sees the word "Blue".
It only sees the numerical vector.

------------------------------------------------------------
NOMINAL DATA

Nominal data classifies information into distinct categories that have no natural order or ranking.
The categories act only as labels or identifiers and cannot be arranged from highest to lowest or best to worst.
Encoding Options: One-Hot Encoding or Label Encoding, depending on the model's needs.

Examples:
- Hair Color
- Gender
- Blood Group
- Nationality
- Place of Residence
- College Major

------------------------------------------------------------
HOW A MODEL INGESTS NOMINAL DATA

A machine-learning model cannot understand text labels directly.

Take one record from a dataset:
- Color = Red
- Blood Group = O+
- Nationality = Nigerian

The model converts these categories into numerical values using an encoding technique.
One-Hot Encoding example:
Red   → [1, 0, 0]
Blue  → [0, 1, 0]
Green → [0, 0, 1]

A record may become: [1, 0, 0, 1, 0, 0, 1]
The model only sees numbers and does not understand the original category names.

------------------------------------------------------------
ORDINAL DATA

Ordinal data classifies information into categories that have a natural order or ranking.
The categories can be arranged from lower to higher levels, but the distance between levels is not necessarily equal.
Encoding Options: Ordinal Encoding.

Examples:
- Education Level: High School → Bachelor's → Master's → PhD
- Customer Satisfaction: Poor → Fair → Good → Excellent
- Class Rankings
- Product Ratings

------------------------------------------------------------
HOW A MODEL INGESTS ORDINAL DATA

Since ordinal categories already have a meaningful order, they can be represented with ranked numerical values.

Take one customer record:
- Satisfaction = Good

The model converts the category into:
Poor      → 1
Fair      → 2
Good      → 3
Excellent → 4

The resulting feature vector becomes: [3]
The model uses the number to understand the ranking relationship between categories.

------------------------------------------------------------
CATEGORICAL DATA IN MACHINE LEARNING

Machine-learning models cannot process text categories directly.
Before training, categorical values must be transformed into numerical representations.
Nominal data is commonly encoded using One-Hot Encoding.
Ordinal data is commonly encoded using ordered numerical values.
After encoding, categorical features become part of the feature vector used by the model.

------------------------------------------------------------
ANALYSIS OF CATEGORICAL DATA

Analysis of categorical data involves using statistical techniques to study data that is grouped into categories.
The main objective is to identify patterns, relationships, and trends among different categories.

------------------------------------------------------------
COMMON METHODS FOR ANALYZING CATEGORICAL DATA

Frequency Tables: Display the count or frequency of each category.
Crosstabulation: Examines the relationship between two categorical variables.
Chi-Square Test: Determines whether there is a significant association between categorical variables.
Contingency Tables: Show the frequency distribution of two or more categorical variables.
Bar Charts and Pie Charts: Visually represent the distribution of categories.
Odds Ratio: Measures the strength of association between two categorical variables.
Logistic Regression: Models the relationship between a categorical outcome and one or more predictor variables.
Multiple Correspondence Analysis (MCA): Analyzes relationships among multiple categorical variables.
ANOVA (Analysis of Variance): Compares the means of different groups to study the effect of categorical variables.
Regression Analysis: Evaluates how categorical predictors influence a continuous outcome.

------------------------------------------------------------
CATEGORICAL DATA ENCODING TECHNIQUES

Categorical encoding is the process of converting categorical values into numerical values that machine-learning models can understand.
Since models only work with numbers, categorical features must be encoded before they can be included in a feature vector.

------------------------------------------------------------
LABEL ENCODING

Label Encoding assigns a unique integer to each category.
Each category is replaced by a numerical label.

Example:
Red   → 0
Green → 1
Blue  → 2

A dataset:
- Red
- Green
- Blue
- Red

Becomes: [0, 1, 2, 0]

Used in:
- Decision Trees
- Random Forests
- XGBoost

Pros:
- Simple to implement
- Memory-efficient
- Fast to process

Cons:
- May incorrectly suggest an order between categories
- Not ideal for nominal data in many algorithms

------------------------------------------------------------
HOW A MODEL INGESTS LABEL-ENCODED DATA

Take one record:
- Color = Red
After Label Encoding: [0]

The model only sees the number 0 and uses it as part of the feature vector.

------------------------------------------------------------
ONE-HOT ENCODING

One-Hot Encoding converts each category into a binary vector containing zeros and one single one.
If there are N categories, each encoded vector contains N positions.
Only one position contains the value 1, indicating the presence of that category.
All remaining positions contain 0.

------------------------------------------------------------
HOW A MODEL INGESTS ONE-HOT ENCODED DATA

Suppose the feature is: Car Color
Vocabulary:
- Red
- Orange
- Blue
- Yellow
- Green
- Black
- Purple
- Brown

Each category is assigned its own position in the vector:
Red    → [1, 0, 0, 0, 0, 0, 0, 0]
Orange → [0, 1, 0, 0, 0, 0, 0, 0]
Blue   → [0, 0, 1, 0, 0, 0, 0, 0]
Yellow → [0, 0, 0, 1, 0, 0, 0, 0]
Green  → [0, 0, 0, 0, 1, 0, 0, 0]
Black  → [0, 0, 0, 0, 0, 1, 0, 0]
Purple → [0, 0, 0, 0, 0, 0, 1, 0]
Brown  → [0, 0, 0, 0, 0, 0, 0, 1]

Take one record from the dataset:
- Color = Red

The model converts it into: [1, 0, 0, 0, 0, 0, 0, 0]

The model never sees the word "Red".
It only sees the numerical feature vector and learns from the binary values.

------------------------------------------------------------
SPARSE REPRESENTATION

A sparse feature is a feature whose values are mostly zeros or empty values.
Many categorical features become sparse after One-Hot Encoding because only one position contains a value of 1
while all other positions contain 0.

------------------------------------------------------------
HOW SPARSE REPRESENTATION WORKS

Suppose the feature is: Car Color

Vocabulary:
- Red
- Orange
- Blue
- Yellow
- Green
- Black
- Purple
- Brown

The One-Hot Encoding for Blue is: [0, 0, 1, 0, 0, 0, 0, 0]

Notice that only one position contains a value of 1.
The remaining positions contain 0.

Since the value 1 appears at position 2 (counting starts from 0), the sparse representation becomes: 2
Instead of storing all eight values, we store only the position of the non-zero value.

------------------------------------------------------------
FROM ONE-HOT VECTOR TO SPARSE REPRESENTATION

Category:
Blue

One-Hot Vector: [0, 0, 1, 0, 0, 0, 0, 0]
Sparse Representation: 2

------------------------------------------------------------
IMPORTANT NOTE

The sparse representation is mainly used to save memory.
The model conceptually learns from the One-Hot Encoded feature vector, not from the sparse index itself.
Sparse representation is simply a more efficient way to store and process One-Hot Encoded data.

------------------------------------------------------------
ORDINAL ENCODING

Ordinal Encoding converts categories into numerical values while preserving their natural order.
It is suitable for ordinal data where ranking matters.

Example:
Low    → 0
Medium → 1
High   → 2

------------------------------------------------------------
HOW A MODEL INGESTS ORDINAL DATA

Take one record:
- Priority = Medium

The model converts it into: [1]

The numerical values preserve the ranking relationship.

------------------------------------------------------------
TARGET ENCODING

Target Encoding replaces each category with the average value of the target variable for that category.
It uses information from the target variable during encoding.

Example:
City      Mean Target
London    1.0
Paris     0.0
Berlin    0.0

------------------------------------------------------------
HOW A MODEL INGESTS TARGET-ENCODED DATA

Take one record:
- City = London
After encoding: [1.0]

The model receives the category's average target value instead of the category name.

------------------------------------------------------------
BINARY ENCODING

Binary Encoding first assigns an integer to each category and then converts that integer into binary form.
The binary digits are distributed across multiple columns.

Example:
Red   → 10
Blue  → 01
Green → 11

------------------------------------------------------------
HOW A MODEL INGESTS BINARY-ENCODED DATA

Take one record:
- Color = Red

The model converts it into: [1, 0]

Each binary digit occupies a separate feature position.

------------------------------------------------------------
FREQUENCY ENCODING

Frequency Encoding replaces a category with the number of times it appears in the dataset.

Example dataset:
- Red
- Green
- Blue
- Red
- Red

Frequency counts:
Red   → 3
Green → 1
Blue  → 1

------------------------------------------------------------
HOW A MODEL INGESTS FREQUENCY-ENCODED DATA

Take one record:
- Color = Red

After encoding: [3]

The model receives the occurrence count instead of the category name.

------------------------------------------------------------
CHOOSING THE RIGHT ENCODING METHOD

One-Hot Encoding
Best For:
- Nominal data
- Small number of categories

Label Encoding
Best For:
- Tree-based models
- Ordered categories

Ordinal Encoding
Best For:
- Ranked categorical data

Target Encoding
Best For:
- High-cardinality features
- Predictive category relationships

Binary Encoding
Best For:
- High-cardinality categorical features

Frequency Encoding
Best For:
- Large datasets
- Popularity-based information

------------------------------------------------------------
CARDINALITY IN DATA

Cardinality refers to the number of unique categories in a categorical feature.

------------------------------------------------------------
LOW CARDINALITY DATA

A feature has low cardinality when it contains only a small number of unique categories.

Examples:

Gender
Male
Female

Blood Group
A
B
AB
O

Country Rating
Low
Medium
High

Number of unique values = Small

------------------------------------------------------------
HIGH CARDINALITY DATA

A feature has high cardinality when it contains many unique categories.

Examples:
ZIP Codes
Product IDs
User IDs
Email Addresses
Customer IDs
Thousands of City Names

Number of unique values = Large

------------------------------------------------------------
EXAMPLE
Suppose you have a feature called Product_ID:
P1001
P1002
P1003
P1004
...
P9999

There are thousands of unique values.
This is a high-cardinality feature.

------------------------------------------------------------
WHY HIGH CARDINALITY IS A PROBLEM

If One-Hot Encoding is applied to: Product_ID
with 10,000 unique categories, 
the model must create: 10,000 new columns

For example:
P1001 → [1, 0, 0, 0, ..., 0]
P1002 → [0, 1, 0, 0, ..., 0]

This wastes memory and increases computational cost.

------------------------------------------------------------
BETTER ENCODING METHODS FOR HIGH CARDINALITY DATA

Target Encoding
Frequency Encoding
Binary Encoding
Hash Encoding

These methods reduce the number of generated columns while preserving useful information.

------------------------------------------------------------
RULE OF THUMB

Low Cardinality

Few unique categories
One-Hot Encoding usually works well

High Cardinality

Many unique categories
One-Hot Encoding becomes inefficient
Binary, Frequency, or Target Encoding are often better choices

------------------------------------------------------------
QUICK EXAM DEFINITION

High Cardinality Data is categorical data that contains a large number of unique categories or distinct values, 
such as Product IDs, ZIP Codes, or Customer IDs. 
Such features often require specialized encoding techniques because traditional One-Hot Encoding can create too many columns.

------------------------------------------------------------
OUTLIERS IN CATEGORICAL DATA

Just like numerical data can contain unusual values, categorical data can contain rare or unusual categories called categorical outliers.
These categories appear very infrequently compared to the rest of the dataset.

Examples: Car Color
Common Categories:
- Red
- Blue
- Black
- White

Rare Categories:
- Mauve
- Avocado
- Lavender

The rare categories are considered categorical outliers because they occur only a few times.

------------------------------------------------------------
WHY CATEGORICAL OUTLIERS ARE A PROBLEM

Suppose a dataset contains:
- Red (5,000 records)
- Blue (4,000 records)
- Black (3,000 records)
- Mauve (2 records)
- Avocado (1 record)

If One-Hot Encoding is used, every category gets its own column.
This means Mauve and Avocado would each receive their own feature even though almost no training data exists for them.

As a result:
- The model learns very little about those categories
- More memory is required
- The feature matrix becomes unnecessarily larger
- The model may overfit to rare categories

------------------------------------------------------------
HOW TO HANDLE CATEGORICAL OUTLIERS

A common solution is to group rare categories into a single category called:
OUT-OF-VOCABULARY (OOV)
or
OTHER

Example:
Original Categories:
- Red
- Blue
- Black
- Mauve
- Avocado

After Grouping:
- Red
- Blue
- Black
- Other

Now:
Mauve   → Other
Avocado → Other

The model learns one weight for all rare categories instead of creating separate features for each one.

------------------------------------------------------------
HOW A MODEL INGESTS OOV DATA

Take one record:
- Color = Avocado

After preprocessing:
Color = Other

One-Hot Encoding:
Red   → [1, 0, 0, 0]
Blue  → [0, 1, 0, 0]
Black → [0, 0, 1, 0]
Other → [0, 0, 0, 1]

The record becomes: [0, 0, 0, 1]

------------------------------------------------------------
HIGH-DIMENSIONAL CATEGORICAL FEATURES

Some categorical features contain an extremely large number of unique categories.

Examples:
Feature            Approximate Categories
English Words      500,000+
US Postal Codes    42,000+
German Surnames    850,000+
Customer IDs       Millions
Product IDs        Millions

These features are called high-cardinality or high-dimensional categorical features.

------------------------------------------------------------
WHY ONE-HOT ENCODING FAILS

Suppose a feature contains: 50,000 unique ZIP codes
One-Hot Encoding would create: 50,000 columns
Most records would contain: [0, 0, 0, 0, ..., 1, ..., 0]

This creates huge sparse vectors.
Problems include:
- High memory consumption
- Slower training
- Slower predictions
- Larger storage requirements

------------------------------------------------------------
EMBEDDINGS

Embeddings are numerical representations that compress large categorical features into smaller dense vectors.

Instead of: ZIP Code = [0, 0, 0, ..., 1, ..., 0]
The model may represent it as: [0.42, -0.18, 0.91, 0.27]

A short vector captures useful information while using far fewer dimensions.

------------------------------------------------------------
WHY EMBEDDINGS ARE BETTER

- Greatly reduce dimensionality
- Train faster
- Require less memory
- Make predictions faster
- Can learn similarities between categories

For very large categorical features, embeddings are usually preferred over One-Hot Encoding.

------------------------------------------------------------
HASHING (THE HASHING TRICK)

Hashing is another technique used to reduce the dimensionality of high-cardinality categorical features.
Instead of creating one column for every category, a hash function maps categories into a fixed number of buckets.

------------------------------------------------------------
HOW HASHING WORKS

Suppose the categories are:
- Red
- Blue
- Green
- Purple
- Orange

A hash function may convert them into:
Red    → Bucket 2
Blue   → Bucket 5
Green  → Bucket 1
Purple → Bucket 2
Orange → Bucket 4

Notice that different categories can sometimes land in the same bucket.
This is called a hash collision.

------------------------------------------------------------
HOW A MODEL INGESTS HASHED DATA

Take one record:
- Color = Red

Hash Function Output: Bucket 2
The encoded vector becomes: [0, 0, 1, 0, 0]

The model only sees the bucket representation.

------------------------------------------------------------
PROS OF HASHING

- Fixed number of dimensions
- Handles new categories automatically
- Memory efficient
- Works well with massive datasets
- No need to store a vocabulary

------------------------------------------------------------
CONS OF HASHING

- Different categories may share the same bucket
- Hash collisions can reduce accuracy
- Less interpretable than One-Hot Encoding

------------------------------------------------------------
COMMON ISSUES IN CATEGORICAL DATA

Categorical data is often created by humans or machine-learning models rather than by direct measurements.
Because categories are assigned by people or algorithms, errors, bias, and inconsistencies can be introduced into the dataset.
These issues can reduce model accuracy and reliability if they are not detected before training.

------------------------------------------------------------
HUMAN RATERS

Human-labeled data is often called Gold Labels.
Gold labels are generally considered higher quality because they are manually reviewed and assigned by people.
However, human-labeled data is not always perfect.

Problems may include:
- Human error
- Personal bias
- Inconsistent labeling
- Misunderstanding of categories
- Malicious labeling

------------------------------------------------------------
INTER-RATER AGREEMENT

Different people may assign different labels to the same example.
This difference is called Inter-Rater Agreement.

Example:
A photo containing a small dog.
Rater 1: Dog
Rater 2: Wolf
Rater 3: Fox

The greater the disagreement, the lower the inter-rater agreement.

------------------------------------------------------------
MACHINE RATERS

Machine-labeled data is often called Silver Labels.
Silver labels are generated automatically by machine-learning models.

Although faster and cheaper than human labeling, machine-generated labels may contain errors.

------------------------------------------------------------
EXAMPLES OF MACHINE LABELING ERRORS

Computer Vision Example:
A model labels:
- Chihuahua → Muffin
- Muffin → Chihuahua

Sentiment Analysis Example: A neutral word receives a negative score.
Toxicity Detection Example: A harmless sentence is incorrectly labeled as toxic.

------------------------------------------------------------
HIGH DIMENSIONALITY

Categorical features often create large feature vectors.
This problem becomes worse when a feature contains many unique categories.

Examples:
Feature                 Categories
English Words           500,000+
US Postal Codes         42,000+
German Surnames         850,000+
Product IDs             Millions
Customer IDs            Millions

------------------------------------------------------------
WHY HIGH DIMENSIONALITY IS A PROBLEM

A large number of categories often produces extremely large feature vectors.

Problems include:
- Increased memory usage
- Slower model training
- Slower predictions
- Higher computational cost
- Greater risk of overfitting

------------------------------------------------------------
HOW TO HANDLE HIGH DIMENSIONALITY

Instead of One-Hot Encoding thousands of categories, dimensionality reduction techniques can be used.

Common techniques include:
- Embeddings
- Hashing
- Target Encoding
- Frequency Encoding
- Binary Encoding

Among these methods, Embeddings are often the preferred solution for large categorical datasets.

------------------------------------------------------------
EMBEDDINGS

Embeddings convert large sparse vectors into smaller dense vectors.

Instead of: [0, 0, 0, 0, 1, 0, 0, 0, ... ]
The category may be represented as: [0.21, -0.36, 0.74, 0.15]

The smaller vector preserves useful information while reducing dimensionality.

------------------------------------------------------------

WHY EMBEDDINGS MATTER

- Reduce feature dimensions
- Reduce memory usage
- Speed up training
- Speed up prediction
- Learn similarities between categories

FEATURE CROSSES

Feature Crosses are created by combining two or more categorical features to form a new feature.
This process is called the Cartesian Product of features.
Feature Crosses help models learn interactions and relationships between features that may not be obvious when the features are used separately.
Like Polynomial Transforms for numerical data, Feature Crosses help linear models learn non-linear patterns.

------------------------------------------------------------
WHY FEATURE CROSSES ARE NEEDED

Suppose a dataset contains two features:
Edge Type
- Smooth
- Toothed
- Lobed

Leaf Arrangement
- Opposite
- Alternate

If these features are used separately, the model learns about each feature individually.
However, the combination of features may contain important information.

For example:
- Smooth + Opposite
- Smooth + Alternate
- Lobed + Opposite
- Lobed + Alternate

These combinations may help identify specific tree species.

------------------------------------------------------------
HOW FEATURE CROSSES WORK

Original Features:
Edges
- Smooth
- Toothed
- Lobed

Arrangement
- Opposite
- Alternate

The Feature Cross creates every possible combination:
- Smooth_Opposite
- Smooth_Alternate
- Toothed_Opposite
- Toothed_Alternate
- Lobed_Opposite
- Lobed_Alternate

This new feature becomes the Cartesian Product of both categorical features.

------------------------------------------------------------
HOW A MODEL INGESTS FEATURE CROSSES

Take one leaf record:
- Edge = Lobed
- Arrangement = Alternate

The crossed feature becomes: Lobed_Alternate
Feature Cross Vector: [0, 0, 0, 0, 0, 1]

The value 1 appears only in the position corresponding to Lobed_Alternate.
All other positions remain 0.
The model learns from the interaction between the two features rather than treating them independently.

------------------------------------------------------------
FROM ORIGINAL FEATURES TO FEATURE CROSS

Original One-Hot Encodings: 
Edges
Smooth  → [1, 0, 0]
Toothed → [0, 1, 0]
Lobed   → [0, 0, 1]

Arrangement
Opposite  → [1, 0]
Alternate → [0, 1]

Take one leaf:
- Lobed
- Alternate

Original Features: [0, 0, 1] + [0, 1]
Feature Cross: [0, 0, 0, 0, 0, 1]

This activates the Lobed_Alternate combination.

------------------------------------------------------------

REAL-WORLD EXAMPLE

Suppose a housing dataset contains:
Neighborhood
- City Center
- Suburb

Home Type
- Apartment
- House

Used separately:
- Neighborhood
- Home Type

Feature Cross:
- CityCenter_Apartment
- CityCenter_House
- Suburb_Apartment
- Suburb_House

A CityCenter_Apartment may have a very different price pattern from a Suburb_Apartment.
Feature Crosses help the model learn these relationships.

------------------------------------------------------------
WHEN TO USE FEATURE CROSSES

Use Feature Crosses when:
- Two or more features interact strongly
- Domain knowledge suggests useful combinations
- Linear models struggle to capture relationships
- Feature interactions are important for prediction

Common applications:
- Advertising
- Search Ranking
- Recommendation Systems
- Housing Price Prediction
- Customer Behavior Modeling

------------------------------------------------------------
DRAWBACK OF FEATURE CROSSES
Feature Crosses increase dimensionality.
Crossing two sparse features creates an even larger sparse feature.

Example:
Feature A = 100 categories
Feature B = 200 categories

Feature Cross Size:
100 × 200 = 20,000 categories
The resulting feature vector becomes much larger and sparser.

------------------------------------------------------------
FEATURE CROSSES VS ONE-HOT ENCODING

One-Hot Encoding
- Represents individual categories
- Learns features separately

Feature Crosses
- Represent category combinations
- Learn interactions between features

Example:
One-Hot Encoding:
- Red
- SUV

Feature Cross:
- Red_SUV

The crossed feature captures information that the separate features cannot express on their own.
