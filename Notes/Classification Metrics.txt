INTRODUCTION TO DATASETS IN SCIKIT‑LEARN

Machine Learning models need data to learn patterns and make predictions.  
Scikit‑Learn provides convenient ways to access datasets for practice, testing, and real‑world applications.

There are three main types of dataset functions:

- fetch_* functions → Download real‑life datasets from the internet (e.g., MNIST via fetch_openml).  
- load_* functions → Load small toy datasets bundled inside Scikit‑Learn (no internet required).  
- make_* functions → Generate synthetic datasets, useful for controlled experiments and debugging.

------------------------------------------------------------  
HOW DATASETS ARE RETURNED

Datasets usually come in two formats:

- Tuple (X, y)  
  - X → Input features (2D NumPy array)  
  - y → Labels or targets (1D NumPy array)

- Bunch object (dictionary‑like with attribute access)  
  - "DESCR" → Description of the dataset  
  - "data" → Input features  
  - "target" → Labels

------------------------------------------------------------  
SPECIAL CASE: fetch_openml()

- By default, returns Pandas DataFrame (inputs) and Pandas Series (labels).  
- For image datasets like MNIST, DataFrames are not ideal.  
- Setting as_frame=False converts them into NumPy arrays, which are easier to reshape and visualize.

Example:  
```python
from sklearn.datasets import fetch_openml
mnist = fetch_openml('mnist_784', as_frame=False)
X, y = mnist.data, mnist.target
```

Here:  
- X.shape = (70000, 784) → 70,000 images, each flattened into 784 pixels (28×28).  
- y.shape = (70000,) → Labels for each image.

------------------------------------------------------------  
CLASSIFICATION METRICS 

Classification models assign data into categories. To check how well a model performs, we use evaluation metrics. 
These metrics help us understand whether the model is making correct predictions, missing important cases, or producing too many false alarms.

------------------------------------------------------------ 
CROSS_VAL_SCORE VS CROSS_VAL_PREDICT

Both functions use k‑fold cross‑validation, but they serve different purposes.

------------------------------------------------------------  
CROSS_VAL_SCORE

- Runs k‑fold cross‑validation  
- Returns evaluation scores (accuracy, RMSE, etc.) for each fold  
- Example: `[0.95, 0.96, 0.96]`  
- Answers the question: **“How well did my model do?”**

------------------------------------------------------------  
CROSS_VAL_PREDICT

- Runs k‑fold cross‑validation  
- Returns predictions for every sample in the training set  
- Example: `[False, False, True, ...]` (predicted labels)  
- Each sample is predicted by a model that did not see that sample during training → “out‑of‑sample” or “clean” predictions  
- Avoids bias that happens if you just call `.predict(X_train)` on data the model already saw  
- Answers the question: **“What did my model actually predict?”**

------------------------------------------------------------  
WORKFLOW

1. Use `cross_val_predict` to get unbiased predictions for each training instance  
2. Compare predictions with true labels using tools like `confusion_matrix`, `precision_score`, `recall_score`  
3. This gives a clearer picture of how the model behaves on unseen data  

-----------------------------------------------------------  
CONFUSION MATRIX 

A confusion matrix is a simple table that compares what the model predicted with what the actual answer was.  
It counts how often the model was correct and what kinds of mistakes it made.

------------------------------------------------------------  
BINARY EXAMPLE (Detecting “5” vs “Not 5”)

|                | Predicted: Not 5 | Predicted: 5 |
|----------------|------------------|--------------|
| Actual: Not 5  | True Negatives (correctly said “not 5”) | False Positives (said “5” when it wasn’t) |
| Actual: 5      | False Negatives (missed a real “5”)     | True Positives (correctly found a “5”)   |

------------------------------------------------------------  
EXAMPLE NUMBERS

```python
cm = confusion_matrix(y_train_5, y_train_pred)
print(cm)
```

Output:  
```
[[53892,   687],
 [ 1891,  3530]]
```

Interpretation:  
- 53,892 True Negatives → correctly said “not 5.”  
- 687 False Positives → wrongly said “5” when it wasn’t.  
- 1,891 False Negatives → missed actual “5s.”  
- 3,530 True Positives → correctly found “5s.”  

True Positives (TP)  
Correctly predicted positive cases.  
Example: correctly detecting a disease.  
Document reference: “True Positives are the cases where the model correctly predicted the positive class…” 

True Negatives (TN)  
Correctly predicted negative cases.  
Example: correctly identifying non‑spam emails.  
Document reference: “True Negatives are the cases where the model correctly predicted the negative class…” 

False Positives (FP)  
Model predicts positive when it is actually negative.  
Example: diagnosing a disease that is not present.  
Document reference: “False Positives occur when the model incorrectly predicts the positive class…” 

False Negatives (FN)  
Model predicts negative when it is actually positive.  
Example: missing a spam email or missing a disease.  
Document reference: “False Negatives happen when the model incorrectly predicts the negative class…” 

------------------------------------------------------------  
WHY IT MATTERS

Accuracy alone can be misleading. The confusion matrix shows:  
- If the model is missing positives (recall problem)  
- If it is predicting too many false alarms (precision problem)  

From this we calculate:  
- Precision = TP / (TP + FP) → reliability of positive predictions  
- Recall = TP / (TP + FN) → how many actual positives are caught  

------------------------------------------------------------  
 PERFECT CLASSIFIER AND THE CONFUSION MATRIX

A perfect classifier means:  
- It never makes mistakes  
- Every “not 5” is correctly predicted as “not 5”  
- Every “5” is correctly predicted as “5”  

So in the confusion matrix:  
- True Negatives (TN) → all non‑5s are correct  
- True Positives (TP) → all 5s are correct  
- False Positives (FP) → zero (never says “5” when it’s not)  
- False Negatives (FN) → zero (never misses a “5”)  

That’s why the matrix only has numbers on the main diagonal (top‑left to bottom‑right). Everything off the diagonal is zero.

Example:  
```python
array([[54579,     0],
       [    0,  5421]])
```

- Top‑left (54579) = all non‑5s correctly classified  
- Bottom‑right (5421) = all 5s correctly classified  
- Off‑diagonal entries = 0 (no mistakes)  

------------------------------------------------------------  
WHY THIS MATTERS

- The diagonal = correct predictions  
- Off‑diagonal = mistakes  
- A perfect classifier’s confusion matrix has only diagonal values  

This makes it easy to see at a glance: if your matrix has numbers outside the diagonal, those are errors.  

------------------------------------------------------------  
ACCURACY

Accuracy measures how many predictions were correct:

Accuracy = (TP + TN) / (TP + TN + FP + FN)

Strengths  
Easy to understand.  
Works well when classes are balanced.

Limitations  
Misleading for imbalanced datasets.  
Treats all errors equally, even when some errors are more serious. 

------------------------------------------------------------  
PRECISION

Precision answers: “When the model says positive, how often is it correct?”  

Formula:  TP / (TP + FP)

- TP (True Positives): correctly predicted positives  
- FP (False Positives): predicted positive but actually negative  

Example: If the model predicts 100 “5s,” and 90 are truly 5s, precision = 90%.  

Useful when false positives are costly.  
Example: medical diagnosis, spam detection.  
“Precision provides insights into the model's ability to make accurate positive predictions…” 

------------------------------------------------------------  
RECALL

Recall answers: “Out of all the actual positives, how many did the model catch?”  

Formula:  TP / (TP + FN)

- FN (False Negatives): actual positives the model missed  

Example: If there are 120 real “5s,” and the model finds 90, recall = 75%.  

Useful when missing positives is dangerous.  
Example: disease detection, security threat detection.  
“Recall…assesses a model's ability to correctly identify all positive instances…” 

------------------------------------------------------------  
WHY BOTH MATTER

- High precision, low recall → cautious model, few false alarms but misses many positives  
- High recall, low precision → generous model, catches most positives but produces many false alarms  
- Balance is often measured by the F1 score, which combines both  

------------------------------------------------------------  
PERFECT CLASSIFIER

A perfect classifier would have:  
- Precision = 100% (no false positives)  
- Recall = 100% (no false negatives)  
- Confusion matrix with only diagonal values (all predictions correct)  

------------------------------------------------------------  
PRECISION/RECALL TRADE‑OFF

How the classifier decides:  
- Each sample gets a score (likelihood of being positive)  
- Compare score to a threshold:  
  - If score > threshold → predict positive  
  - If score ≤ threshold → predict negative  

Changing the threshold:  
- Lower threshold → more positives predicted  
  - Recall goes up (catch more positives)  
  - Precision goes down (more false alarms)  
- Higher threshold → fewer positives predicted  
  - Precision goes up (fewer false alarms)  
  - Recall goes down (miss more positives)  

Example:  
- With 6 real “5s” and 1 “6”:  
  - Threshold in the middle → 4 TP + 1 FP → Precision = 80%, Recall = 67%  
  - Higher threshold → 3 TP + 0 FP → Precision = 100%, Recall = 50%  

Why this matters:  
- If false positives are costly → aim for high precision  
- If false negatives are costly → aim for high recall  
- Often balance them using the F1 score  

------------------------------------------------------------  
F1 SCORE SIMPLIFIED

The F1 score is a way to combine precision and recall into a single number.  
It is the harmonic mean of precision and recall, which means it gives more weight to low values.  
A classifier only gets a high F1 score if both precision and recall are high.


Formula = 2 × (Precision × Recall) / (Precision + Recall)



Where:  
- TP = True Positives  
- FP = False Positives  
- FN = False Negatives  

Useful for imbalanced datasets.  
Balances false positives and false negatives.  
“The F1-Score is…calculated using the harmonic mean of precision and recall…” 

------------------------------------------------------------  
EXAMPLE

```python
from sklearn.metrics import f1_score
f1_score(y_train_5, y_train_pred)
```

F1 = 2 * (Precision * Recall) / (Precision + Recall)

Using Precision = 0.84 and Recall = 0.65:

Step 1: Multiply precision and recall  
0.84 * 0.65 = 0.546

Step 2: Multiply by 2  
2 * 0.546 = 1.092

Step 3: Add precision and recall  
0.84 + 0.65 = 1.49

Step 4: Divide  
F1 = 1.092 / 1.49  
F1 ≈ 0.73

------------------------------------------------------------  
WHY IT MATTERS

The F1 score favors classifiers that have similar precision and recall.  
This is not always what you want:  

- If you are detecting videos safe for kids, you mostly care about precision.  
  Better to reject many good videos (low recall) but keep only safe ones (high precision).  

- If you are detecting shoplifters in surveillance images, you mostly care about recall.  
  Even if precision is low (many false alarms), it’s fine as long as almost all shoplifters are caught.  

Unfortunately, you can’t maximize both at the same time. Increasing precision reduces recall, and increasing recall reduces precision. 
This is the precision/recall trade‑off.  

------------------------------------------------------------  
DECISION FUNCTION AND THRESHOLD SIMPLIFIED

Normally, `predict()` just outputs yes/no (positive/negative).  
But inside, the classifier is computing a score for each sample — how strongly it believes the sample belongs to the positive class.  

- If the score is above a threshold → predict positive  
- If the score is below the threshold → predict negative  

By default, `SGDClassifier` uses threshold = 0.  

------------------------------------------------------------  
USING `decision_function()`

```python
y_scores = sgd_clf.decision_function([some_digit])
```

- This gives the raw score (e.g., 2164.22).  
- You can then set your own threshold:  

```python
threshold = 0
y_pred = (y_scores > threshold)   # True → positive
```

Raise the threshold:  

```python
threshold = 3000
y_pred = (y_scores > threshold)   # False → negative
```

- Raising the threshold → stricter model, fewer positives predicted → higher precision, lower recall  
- Lowering the threshold → more generous model, more positives predicted → higher recall, lower precision  

------------------------------------------------------------  
WHY THIS MATTERS

You can tune the threshold depending on your project:  
- If false alarms are costly → raise threshold (prioritize precision)  
- If missing positives is costly → lower threshold (prioritize recall)  

------------------------------------------------------------  
CHOOSING A THRESHOLD SIMPLIFIED

Here’s the simple idea behind choosing a threshold.

------------------------------------------------------------  
STEP 1: GET DECISION SCORES  

Instead of just predictions (True/False), ask the model for confidence scores:  

```python
y_scores = cross_val_predict(sgd_clf, X_train, y_train_5, cv=3,
                             method="decision_function")
```

Now you have a score for every training sample — positive if the model leans toward “5,” negative if it leans toward “not 5.”  

------------------------------------------------------------  
STEP 2: COMPUTE PRECISION & RECALL AT ALL THRESHOLDS  

```python
from sklearn.metrics import precision_recall_curve
precisions, recalls, thresholds = precision_recall_curve(y_train_5, y_scores)
```

This gives you:  
- precisions → precision values at different thresholds  
- recalls → recall values at different thresholds  
- thresholds → the cutoff values tested  

------------------------------------------------------------  
STEP 3: PLOT CURVES  

```python
plt.plot(thresholds, precisions[:-1], "b--", label="Precision")
plt.plot(thresholds, recalls[:-1], "g-", label="Recall")
plt.vlines(3000, 0, 1.0, "k", "dotted", label="threshold")
plt.legend()
plt.show()
```

This shows how precision rises and recall falls as you raise the threshold.  

------------------------------------------------------------  
STEP 4: PICK YOUR TARGET  

If you want 90% precision, find the lowest threshold that achieves it:  

```python
idx_for_90_precision = (precisions >= 0.90).argmax()
threshold_for_90_precision = thresholds[idx_for_90_precision]
```

Then make predictions using that threshold:  

```python
y_train_pred_90 = (y_scores >= threshold_for_90_precision)
```

------------------------------------------------------------  
STEP 5: CHECK THE TRADE‑OFF  

At that threshold:  
- Precision ≈ 90% (trustworthy positives)  
- Recall ≈ 48% (misses more actual 5s)  

------------------------------------------------------------  
SIMPLE TAKEAWAY  

You choose the threshold by looking at precision/recall curves and picking the cutoff that matches your project’s needs.  
- Higher threshold → higher precision, lower recall  
- Lower threshold → higher recall, lower precision  

------------------------------------------------------------  
ROC CURVE

The ROC curve (Receiver Operating Characteristic curve) is a tool for evaluating binary classifiers.
It shows how well a model separates positive and negative classes at different thresholds.

It plots:
Y‑axis: True Positive Rate (TPR) — also called Recall or Sensitivity
X‑axis: False Positive Rate (FPR) — also called Fall‑out

So the ROC curve is:
Sensitivity vs. (1 – Specificity)

Where:
Specificity = True Negative Rate (TNR)
FPR = 1 – TNR
The ROC curve 

A good classifier’s ROC curve:
rises quickly toward the top-left corner
meaning high recall and low false positives
A random classifier is a diagonal line from (0,0) to (1,1).

“The ROC curve visually illustrates how the model's performance changes…” 

------------------------------------------------------------  
AUC (AREA UNDER ROC CURVE)
The Area Under the ROC Curve (AUC) is a single number that summarizes the entire ROC curve.

It answers one question:
How well does the classifier separate positive and negative classes?

AUC = 0.5 → random guessing  
Same as flipping a coin, ROC curve is the diagonal line

AUC = 1.0 → perfect model
Always ranks positive samples higher than negative samples, ROC curve hugs the top-left corner

AUC < 0.5  Worse than random
Model is systematically wrong
(You could invert its predictions to get >0.5)

Useful for comparing models and handling imbalanced datasets.  
“The Area Under the ROC Curve (AUC) quantifies the overall performance…” 

------------------------------------------------------------  
LIMITATIONS OF ROC‑AUC

Does not show the cost of false positives or false negatives.  
Should be used together with precision, recall, and F1‑Score.

------------------------------------------------------------  
WHAT MULTICLASS CLASSIFICATION MEANS

Binary classifiers handle 2 classes.  
Multiclass classifiers handle more than 2 classes (for example, digits 0–9).

Some algorithms support multiclass classification natively:  
LogisticRegression  
RandomForestClassifier  
GaussianNB  

Others are strictly binary:  
SGDClassifier  
SVC  

For binary‑only algorithms, Scikit‑Learn automatically applies a multiclass strategy.

------------------------------------------------------------  
STRATEGY 1: ONE‑VERSUS‑REST (OvR)

OvR trains one binary classifier per class.

For MNIST (10 digits), you train 10 classifiers:  
0 vs all  
1 vs all  
…  
9 vs all  

How prediction works:  
Run the input through all classifiers.  
Each classifier outputs a score.  
Pick the class with the highest score.

Advantages:  
Simple  
Works well for most algorithms  
Scikit‑Learn uses OvR automatically for many models

------------------------------------------------------------  
STRATEGY 2: ONE‑VERSUS‑ONE (OvO)

OvO trains one classifier for every pair of classes.

For MNIST (10 classes):  
N × (N − 1) / 2 = 10 × 9 / 2 = 45 classifiers

Examples:  
0 vs 1  
0 vs 2  
…  
8 vs 9  

How prediction works:  
Run the input through all 45 classifiers.  
Each classifier votes for one class.  
The class with the most votes wins.

Advantages:  
Each classifier trains on only two classes → small training sets  
Useful for algorithms that scale poorly with dataset size (like SVMs)

Disadvantages:  
Many classifiers  
More computation during prediction

------------------------------------------------------------  
WHICH STRATEGY IS BETTER

For SVMs, OvO is often faster and preferred.  
For most other algorithms, OvR is simpler and works well.

Scikit‑Learn automatically chooses:  
OvR for many models  
OvO for SVC

------------------------------------------------------------  
SCIKIT‑LEARN AUTOMATIC BEHAVIOR

If you use a binary‑only classifier (like SVC) on a multiclass dataset:  
Scikit‑Learn detects this  
It automatically applies OvR or OvO  
No manual coding is required
