INTRODUCTION TO DATASETS IN SCIKIT‑LEARN

Machine Learning models need data to learn patterns and make predictions.  
Scikit‑Learn provides convenient ways to access datasets for practice, testing, and real‑world applications.

There are three main types of dataset functions:

- fetch_* functions → Download real‑life datasets from the internet (e.g., MNIST via fetch_openml).  
- load_* functions → Load small toy datasets bundled inside Scikit‑Learn (no internet required).  
- make_* functions → Generate synthetic datasets, useful for controlled experiments and debugging.

------------------------------------------------------------  
HOW DATASETS ARE RETURNED

Datasets usually come in two formats:

- Tuple (X, y)  
  - X → Input features (2D NumPy array)  
  - y → Labels or targets (1D NumPy array)

- Bunch object (dictionary‑like with attribute access)  
  - "DESCR" → Description of the dataset  
  - "data" → Input features  
  - "target" → Labels

------------------------------------------------------------  
SPECIAL CASE: fetch_openml()

- By default, returns Pandas DataFrame (inputs) and Pandas Series (labels).  
- For image datasets like MNIST, DataFrames are not ideal.  
- Setting as_frame=False converts them into NumPy arrays, which are easier to reshape and visualize.

Example:  
```python
from sklearn.datasets import fetch_openml
mnist = fetch_openml('mnist_784', as_frame=False)
X, y = mnist.data, mnist.target
```

Here:  
- X.shape = (70000, 784) → 70,000 images, each flattened into 784 pixels (28×28).  
- y.shape = (70000,) → Labels for each image.

------------------------------------------------------------  
CLASSIFICATION METRICS 

Classification models assign data into categories. To check how well a model performs, we use evaluation metrics. 
These metrics help us understand whether the model is making correct predictions, missing important cases, or producing too many false alarms.

------------------------------------------------------------ 
CROSS_VAL_SCORE VS CROSS_VAL_PREDICT

Both functions use k‑fold cross‑validation, but they serve different purposes.
 k‑fold cross‑validation: dataset is split into k equal parts, and the model is trained and tested k times, each time using a different part as the test set.

------------------------------------------------------------  
CROSS_VAL_SCORE

- Runs k‑fold cross‑validation  
- Returns evaluation scores (accuracy, RMSE, etc.) for each fold  
- Example: `[0.95, 0.96, 0.96]`  
- Answers the question: “How well did my model do?”

------------------------------------------------------------  
CROSS_VAL_PREDICT

- Runs k‑fold cross‑validation  
- Returns predictions for every sample in the training set  
- Example: `[False, False, True, ...]` (predicted labels)  
- Each sample is predicted by a model that did not see that sample during training → “out‑of‑sample” or “clean” predictions  
- Avoids bias that happens if you just call `.predict(X_train)` on data the model already saw  
- Answers the question: “What did my model actually predict?”

------------------------------------------------------------  
WORKFLOW

1. Use `cross_val_predict` to get unbiased predictions for each training instance  
2. Compare predictions with true labels using tools like `confusion_matrix`, `precision_score`, `recall_score`  
3. This gives a clearer picture of how the model behaves on unseen data  

-----------------------------------------------------------  
CONFUSION MATRIX 

A confusion matrix is a simple table that compares what the model predicted with what the actual answer was.  
It counts how often the model was correct and what kinds of mistakes it made.

------------------------------------------------------------  
BINARY EXAMPLE (Detecting “5” vs “Not 5”)

|                | Predicted: Not 5 | Predicted: 5 |
|----------------|------------------|--------------|
| Actual: Not 5  | True Negatives (correctly said “not 5”) | False Positives (said “5” when it wasn’t) |
| Actual: 5      | False Negatives (missed a real “5”)     | True Positives (correctly found a “5”)   |

------------------------------------------------------------  
EXAMPLE NUMBERS

```python
cm = confusion_matrix(y_train_5, y_train_pred)
print(cm)
```

Output:  
```
[[53892,   687],
 [ 1891,  3530]]
```

Interpretation:  
- 53,892 True Negatives → correctly said “not 5.”  
- 687 False Positives → wrongly said “5” when it wasn’t.  
- 1,891 False Negatives → missed actual “5s.”  
- 3,530 True Positives → correctly found “5s.”  

True Positives (TP)  
Correctly predicted positive cases.  
Example: correctly detecting a disease.  
Document reference: “True Positives are the cases where the model correctly predicted the positive class…” 

True Negatives (TN)  
Correctly predicted negative cases.  
Example: correctly identifying non‑spam emails.  
Document reference: “True Negatives are the cases where the model correctly predicted the negative class…” 

False Positives (FP)  
Model predicts positive when it is actually negative.  
Example: diagnosing a disease that is not present.  
Document reference: “False Positives occur when the model incorrectly predicts the positive class…” 

False Negatives (FN)  
Model predicts negative when it is actually positive.  
Example: missing a spam email or missing a disease.  
Document reference: “False Negatives happen when the model incorrectly predicts the negative class…” 

------------------------------------------------------------  
WHY IT MATTERS

Accuracy alone can be misleading. The confusion matrix shows:  
- If the model is missing positives (recall problem)  
- If it is predicting too many false alarms (precision problem)  

From this we calculate:  
- Precision = TP / (TP + FP) → reliability of positive predictions  
- Recall = TP / (TP + FN) → how many actual positives are caught  

------------------------------------------------------------  
 PERFECT CLASSIFIER AND THE CONFUSION MATRIX

A perfect classifier means:  
- It never makes mistakes  
- Every “not 5” is correctly predicted as “not 5”  
- Every “5” is correctly predicted as “5”  

So in the confusion matrix:  
- True Negatives (TN) → all non‑5s are correct  
- True Positives (TP) → all 5s are correct  
- False Positives (FP) → zero (never says “5” when it’s not)  
- False Negatives (FN) → zero (never misses a “5”)  

That’s why the matrix only has numbers on the main diagonal (top‑left to bottom‑right). Everything off the diagonal is zero.

Example:  
```python
array([[54579,     0],
       [    0,  5421]])
```

- Top‑left (54579) = all non‑5s correctly classified  
- Bottom‑right (5421) = all 5s correctly classified  
- Off‑diagonal entries = 0 (no mistakes)  

------------------------------------------------------------  
FALSE POSITIVE RATE

The false positive rate (FPR) is the proportion of all actual negatives that were incorrectly classified as positives. 
It represents the model’s probability of raising a false alarm.

Formula: False Positive Rate = FP / (FP + TN)

False positives are actual negatives that were misclassified as positives, which is why they appear in the numerator. 
In the spam classification example, FPR measures the fraction of legitimate emails that were incorrectly labeled as spam, the model’s false alarm rate.

A perfect model would have zero false positives and therefore an FPR of 0.0, meaning a 0% false alarm rate.

For imbalanced datasets, FPR is generally more informative than accuracy because it focuses specifically 
on how often the model incorrectly flags negatives as positives. However, when the number of actual negatives is very small, 
FPR can become unstable. For example, if a dataset contains only four actual negatives, 
one misclassification results in an FPR of 25%, and a second misclassification increases it to 50%. 
In such cases, precision may be a more stable metric for evaluating false positives.

Strengths  
- More informative than accuracy for imbalanced datasets.  
- Directly measures the model’s false alarm rate.  

Limitations  
- Volatile when actual negatives are very few.  
- Does not consider false negatives or positive-class performance.  

------------------------------------------------------------  
ACCURACY

Accuracy is the proportion of all classifications that were correct, whether positive or negative.

Formula (TXT format):  
Accuracy = (TP + TN) / (TP + TN + FP + FN)

A perfect model has zero false positives and zero false negatives, giving an accuracy of 1.0 (100%).

Accuracy uses all four confusion-matrix outcomes (TP, FP, TN, FN).+ When the dataset is balanced, 
with similar numbers of examples in each class, accuracy can serve as a coarse-grained measure of model quality. 
For this reason, it is often the default metric for generic or unspecified tasks.

However, accuracy becomes misleading when the dataset is imbalanced or when one type of mistake (FP or FN) is more costly. 
In heavily imbalanced datasets, where one class appears very rarely (for example, 1% of the time), 
a model that predicts negative for every example would still achieve 99% accuracy, despite being useless.

Strengths  
- Easy to understand.  
- Works well when classes are balanced.  

Limitations  
- Misleading for imbalanced datasets.  
- Treats all errors equally, even when some errors are more serious.  

------------------------------------------------------------  
PRECISION

Precision answers the question: “When the model predicts positive, how often is it correct?”

Formula: Precision = TP / (TP + FP)

TP (True Positives): correctly predicted positives  
FP (False Positives): predicted positive but actually negative

Example: If the model predicts 100 “5s” and 90 are truly 5s, precision = 90%.

Precision measures the proportion of the model’s positive predictions that are actually positive. 
In the spam classification example, precision is the fraction of emails labeled as spam that were truly spam. 
A perfect model would have zero false positives and therefore a precision of 1.0.

Precision is especially useful when false positives are costly. 
Examples include medical diagnosis, fraud detection, and spam filtering, where incorrectly predicting a positive can have serious consequences.

However, in extremely imbalanced datasets where the number of actual positives is very low (for example, only 1–2 positive examples), 
precision becomes less meaningful because a single false positive can drastically change the metric.

Precision improves when false positives decrease. Recall improves when false negatives decrease. 
Because increasing the classification threshold usually reduces false positives but increases false negatives (and lowering the threshold does the opposite), precision and recall often move in opposite directions. Improving one typically worsens the other.

Strengths  
- Useful when false positives are costly.  
- Measures reliability of positive predictions.  

Limitations  
- Less meaningful when actual positives are extremely rare.  
- Often inversely related to recall due to threshold effects.

------------------------------------------------------------  
RECALL

Recall answers the question: “Out of all the actual positives, how many did the model correctly identify?”

Formula: Recall = TP / (TP + FN)

FN (False Negatives): actual positives the model missed.

Example: If there are 120 real “5s” and the model finds 90, recall = 75%.

Recall measures the proportion of actual positives that were correctly classified as positives. 
In the spam classification example, recall represents the fraction of spam emails that the model successfully detected. 
This is why recall is also called the true positive rate (TPR) or probability of detection.

A perfect model would have zero false negatives and therefore a recall of 1.0, meaning a 100% detection rate.

In imbalanced datasets where actual positives are rare, recall is more meaningful than accuracy 
because it focuses on the model’s ability to identify all positive instances. 
In applications like disease detection or security threat identification, missing a positive case 
can be far more dangerous than raising a false alarm. A false negative often carries more serious consequences than a false positive.

Recall improves when false negatives decrease. Precision improves when false positives decrease. 
Because adjusting the classification threshold affects FP and FN in opposite directions, 
recall and precision often show an inverse relationship: improving one typically worsens the other.

Strengths  
- Useful when missing positives is dangerous.  
- Measures the model’s ability to detect all positive instances.  

Limitations  
- Does not consider false positives.  
- Can be misleading if positives are extremely rare and context is ignored.

------------------------------------------------------------  
CHOICE OF METRIC AND TRADEOFFS

The metric you choose to prioritize when evaluating a model or selecting a classification threshold depends on the costs, 
benefits, and risks of the specific problem. Different applications value different types of correctness.
In the spam classification example, it may make sense to prioritize recall (catching all spam), precision 
(ensuring spam-labeled emails are truly spam), or a balanced combination of the two, above some minimum acceptable accuracy level.

Accuracy  
Use as a rough indicator of model training progress or convergence for balanced datasets.  
For evaluating model performance, use accuracy only in combination with other metrics.  
Avoid using accuracy alone for imbalanced datasets, consider alternative metrics.

Recall (True positive rate)  
Use when false negatives are more expensive than false positives.  
Useful in scenarios where missing a positive case is dangerous, such as disease detection or security threat identification.

False positive rate  
Use when false positives are more expensive than false negatives.  
Useful when false alarms cause significant cost or disruption.

Precision  
Use when it is very important for positive predictions to be accurate.  
Useful in cases like spam filtering or medical diagnosis where false positives are costly.

WHY BOTH MATTER

High precision, low recall → a cautious model that produces few false alarms but misses many actual positives.  
High recall, low precision → a generous model that catches most positives but also produces many false alarms.  
A balance between precision and recall is often measured using the F1 score, which combines both metrics into a single value.

------------------------------------------------------------  
PERFECT CLASSIFIER

A perfect classifier would have:  
- Precision = 100% (no false positives)  
- Recall = 100% (no false negatives)  
- Confusion matrix with only diagonal values (all predictions correct)  

------------------------------------------------------------  
PRECISION/RECALL TRADE‑OFF

How the classifier decides:  
- Each sample gets a score (likelihood of being positive)  
- Compare score to a threshold:  
  - If score > threshold → predict positive  
  - If score ≤ threshold → predict negative  

Changing the threshold:  
- Lower threshold → more positives predicted  
  - Recall goes up (catch more positives)  
  - Precision goes down (more false alarms)  
- Higher threshold → fewer positives predicted  
  - Precision goes up (fewer false alarms)  
  - Recall goes down (miss more positives)  

Example:  
- With 6 real “5s” and 1 “6”:  
  - Threshold in the middle → 4 TP + 1 FP → Precision = 80%, Recall = 67%  
  - Higher threshold → 3 TP + 0 FP → Precision = 100%, Recall = 50%  

Why this matters:  
- If false positives are costly → aim for high precision  
- If false negatives are costly → aim for high recall  
- Often balance them using the F1 score  

------------------------------------------------------------  
F1 SCORE SIMPLIFIED

The F1 score is a way to combine precision and recall into a single number.  
It is the harmonic mean of precision and recall, which means it gives more weight to low values.  
A classifier only gets a high F1 score if both precision and recall are high.


Formula = 2 × (Precision × Recall) / (Precision + Recall)

Where:  
- TP = True Positives  
- FP = False Positives  
- FN = False Negatives  

Useful for imbalanced datasets.  
Balances false positives and false negatives.  
“The F1-Score is…calculated using the harmonic mean of precision and recall…” 

------------------------------------------------------------  
EXAMPLE

```python
from sklearn.metrics import f1_score
f1_score(y_train_5, y_train_pred)
```

F1 = 2 * (Precision * Recall) / (Precision + Recall)

Using Precision = 0.84 and Recall = 0.65:

Step 1: Multiply precision and recall  
0.84 * 0.65 = 0.546

Step 2: Multiply by 2  
2 * 0.546 = 1.092

Step 3: Add precision and recall  
0.84 + 0.65 = 1.49

Step 4: Divide  
F1 = 1.092 / 1.49  
F1 ≈ 0.73

------------------------------------------------------------  
WHY IT MATTERS

The F1 score favors classifiers that have similar precision and recall.  
This is not always what you want:  

- If you are detecting videos safe for kids, you mostly care about precision.  
  Better to reject many good videos (low recall) but keep only safe ones (high precision).  

- If you are detecting shoplifters in surveillance images, you mostly care about recall.  
  Even if precision is low (many false alarms), it’s fine as long as almost all shoplifters are caught.  

Unfortunately, you can’t maximize both at the same time. Increasing precision reduces recall, and increasing recall reduces precision. 
This is the precision/recall trade‑off.  

------------------------------------------------------------  
DECISION FUNCTION AND THRESHOLD SIMPLIFIED

Normally, `predict()` just outputs yes/no (positive/negative).  
But inside, the classifier is computing a score for each sample, how strongly it believes the sample belongs to the positive class.  

- If the score is above a threshold → predict positive  
- If the score is below the threshold → predict negative  

By default, `SGDClassifier` uses threshold = 0.  

------------------------------------------------------------  
USING `decision_function()`

```python
y_scores = sgd_clf.decision_function([some_digit])
```

- This gives the raw score (e.g., 2164.22).  
- You can then set your own threshold:  

```python
threshold = 0
y_pred = (y_scores > threshold)   # True → positive
```

Raise the threshold:  

```python
threshold = 3000
y_pred = (y_scores > threshold)   # False → negative
```

- Raising the threshold → stricter model, fewer positives predicted → higher precision, lower recall  
- Lowering the threshold → more generous model, more positives predicted → higher recall, lower precision  

------------------------------------------------------------  
WHY THIS MATTERS

You can tune the threshold depending on your project:  
- If false alarms are costly → raise threshold (prioritize precision)  
- If missing positives is costly → lower threshold (prioritize recall)  

------------------------------------------------------------  
CHOOSING A THRESHOLD SIMPLIFIED

Here’s the simple idea behind choosing a threshold.

------------------------------------------------------------  
STEP 1: GET DECISION SCORES  

Instead of just predictions (True/False), ask the model for confidence scores:  

```python
y_scores = cross_val_predict(sgd_clf, X_train, y_train_5, cv=3,
                             method="decision_function")
```

Now you have a score for every training sample, positive if the model leans toward “5,” negative if it leans toward “not 5.”  

------------------------------------------------------------  
STEP 2: COMPUTE PRECISION & RECALL AT ALL THRESHOLDS  

```python
from sklearn.metrics import precision_recall_curve
precisions, recalls, thresholds = precision_recall_curve(y_train_5, y_scores)
```

This gives you:  
- precisions → precision values at different thresholds  
- recalls → recall values at different thresholds  
- thresholds → the cutoff values tested  

------------------------------------------------------------  
STEP 3: PLOT CURVES  

```python
plt.plot(thresholds, precisions[:-1], "b--", label="Precision")
plt.plot(thresholds, recalls[:-1], "g-", label="Recall")
plt.vlines(3000, 0, 1.0, "k", "dotted", label="threshold")
plt.legend()
plt.show()
```

This shows how precision rises and recall falls as you raise the threshold.  

------------------------------------------------------------  
STEP 4: PICK YOUR TARGET  

If you want 90% precision, find the lowest threshold that achieves it:  

```python
idx_for_90_precision = (precisions >= 0.90).argmax()
threshold_for_90_precision = thresholds[idx_for_90_precision]
```

Then make predictions using that threshold:  

```python
y_train_pred_90 = (y_scores >= threshold_for_90_precision)
```

------------------------------------------------------------  
STEP 5: CHECK THE TRADE‑OFF  

At that threshold:  
- Precision ≈ 90% (trustworthy positives)  
- Recall ≈ 48% (misses more actual 5s)  

------------------------------------------------------------  
SIMPLE TAKEAWAY  

You choose the threshold by looking at precision/recall curves and picking the cutoff that matches your project’s needs.  
- Higher threshold → higher precision, lower recall  
- Lower threshold → higher recall, lower precision  

------------------------------------------------------------  
ROC (RECEIVER‑OPERATING CHARACTERISTIC CURVE)

The ROC curve is a visual representation of model performance across all classification thresholds. 
The name “receiver operating characteristic” comes from WWII radar detection, where similar curves were used to measure signal detection performance.

The ROC curve is created by calculating the true positive rate (TPR) and false positive rate (FPR) at many threshold values,
then plotting TPR on the vertical axis over FPR on the horizontal axis.

TPR (True Positive Rate) is also called recall or sensitivity.  
FPR (False Positive Rate) is also called fall‑out.

Because specificity = true negative rate (TNR), and FPR = 1, 
specificity, the ROC curve can be interpreted as sensitivity versus (1 – specificity).

A good classifier’s ROC curve rises sharply toward the top‑left corner, indicating high recall and low false positives.
A perfect model would reach the point (0, 1), meaning FPR = 0 and TPR = 1 at some threshold.
A random classifier produces a diagonal line from (0, 0) to (1, 1).

The ROC curve visually illustrates how the model’s performance changes as the threshold moves, 
showing the tradeoff between detecting positives and avoiding false alarms.

Strengths  
- Shows model performance across all thresholds.  
- Useful for comparing classifiers.  
- Easy to interpret visually.

Limitations  
- Less informative for heavily imbalanced datasets.  
- Does not show precision or false negatives directly.  

------------------------------------------------------------  
AUC (AREA UNDER THE CURVE)

The Area Under the ROC Curve (AUC) represents the probability that the model, 
when given a randomly chosen positive and negative example, will rank the positive higher than the negative.

A perfect model has an AUC of 1.0. This means there is a 100% chance that the model will assign a higher score 
to a random positive example than to a random negative 
example. AUC reflects how well the model separates the two classes, independent of the threshold chosen.

In practical terms, a spam classifier with AUC = 1.0 always assigns a higher spam probability to a random spam email
than to a random legitimate email. The final classification still depends on the threshold, but the ranking is always correct.

A model that performs no better than random guessing has a ROC curve that is a diagonal line from (0,0) to (1,1). 
Its AUC is 0.5, meaning it correctly ranks a random positive above a random negative only half the time. 
For example, a spam classifier with AUC = 0.5 assigns higher spam probability to a random spam email only 50% of the time.

AUC is useful for comparing models because it summarizes the entire ROC curve into a single number. 
The model with the higher AUC is generally better at separating positive and negative classes.

AUC = 1.0 → perfect model  
Always ranks positives higher than negatives.

AUC = 0.5 → random guessing  
Same as flipping a coin.

AUC < 0.5 → worse than random  
Model is systematically wrong; inverting its predictions would give an AUC above 0.5.

Strengths  
- Threshold‑independent measure of ranking quality.  
- Useful for comparing different models.  
- Intuitive interpretation as a probability.

Limitations  
- Less reliable for highly imbalanced datasets.  
- Does not show performance at a specific threshold.  

------------------------------------------------------------  
AUC AND ROC FOR CHOOSING MODEL AND THRESHOLD

AUC is a useful measure for comparing the performance of two different models, as long as the dataset is roughly balanced. 
The model with the greater area under the curve is generally the better one because it ranks positive 
examples higher than negative examples more consistently.

The ROC curve shows how the model performs across all thresholds. 
Points on the ROC curve that lie closest to (0,1) represent the best-performing thresholds for that model. 
These points indicate high true positive rate (TPR) and low false positive rate (FPR).

Choosing a threshold depends on which metric matters most for the specific use case. Consider three points on the ROC curve:

Point A  
A threshold with a lower false positive rate. Useful when false alarms are expensive or disruptive. This threshold reduces FPR even if TPR decreases.

Point B  
A threshold that balances TPR and FPR. Useful when the costs of false positives and false negatives are roughly equal.

Point C  
A threshold that maximizes true positive rate. Useful when missing positives is highly costly and false positives are cheap. This threshold increases TPR even if FPR rises.

LIMITATIONS OF ROC‑AUC

Does not show the cost of false positives or false negatives.  
Does not indicate how the model performs at a specific threshold.  
Should be used together with precision, recall, and F1‑score for a complete evaluation.  

------------------------------------------------------------  
PREDICTION BIAS

Prediction bias is a quick check that compares the average of the model’s predictions to the average of the true labels in the dataset. 
It helps identify early problems in the model or the data.

If 5% of the emails in the training data are spam, the model should also predict spam about 5% of the time on average. 
In this case, the mean of the labels is 0.05, and the mean of the model’s predictions should also be 0.05. 
When these two means match, the model has zero prediction bias. 
The model may still have other issues, but at least its overall prediction rate aligns with the true distribution.

If the model instead predicts spam 50% of the time, something is wrong. The training data may be biased, the new data may be different from the training data, or the model itself may be flawed. Any significant difference between the mean of predictions and the mean of true labels indicates prediction bias.

Prediction bias can be caused by:  
- Biases or noise in the data, including biased sampling in the training set  
- Too‑strong regularization, which oversimplifies the model  
- Bugs in the model training pipeline  
- Insufficient or incomplete features provided to the model

MULTICLASS CLASSIFICATION

Multiclass classification extends binary classification to more than two classes. 
If each example belongs to only one class, the problem can be broken down into multiple binary classification tasks. 
One class is treated as the positive class, and all remaining classes are grouped together as the negative class. 
This process can be repeated for each class.

For example, in a three‑class problem with labels A, B, and C, you could first build a binary classifier that separates C from A+B. 
Then, a second binary classifier can split A from B within the A+B group. 
This approach allows binary classifiers to handle multiclass problems.

A common example of multiclass classification is handwriting recognition, where the model must classify digits from 0 to 9.

Some algorithms support multiclass classification natively:  
- LogisticRegression  
- RandomForestClassifier  
- GaussianNB  

Other algorithms are strictly binary:  
- SGDClassifier  
- SVC  

For binary‑only algorithms, Scikit‑Learn automatically applies a multiclass strategy such as one‑versus‑rest or one‑versus‑one.

If class membership is not exclusive and an example can belong to multiple classes at once, the problem is known as multi‑label classification.

------------------------------------------------------------  
STRATEGY 1: ONE‑VERSUS‑REST (OvR)

OvR trains one binary classifier per class.

For MNIST (10 digits), you train 10 classifiers:  
0 vs all  
1 vs all  
…  
9 vs all  

How prediction works:  
Run the input through all classifiers.  
Each classifier outputs a score.  
Pick the class with the highest score.

Advantages:  
Simple  
Works well for most algorithms  
Scikit‑Learn uses OvR automatically for many models

------------------------------------------------------------  
STRATEGY 2: ONE‑VERSUS‑ONE (OvO)

OvO trains one classifier for every pair of classes.

For MNIST (10 classes):  
N × (N − 1) / 2 = 10 × 9 / 2 = 45 classifiers

Examples:  
0 vs 1  
0 vs 2  
…  
8 vs 9  

How prediction works:  
Run the input through all 45 classifiers.  
Each classifier votes for one class.  
The class with the most votes wins.

Advantages:  
Each classifier trains on only two classes → small training sets  
Useful for algorithms that scale poorly with dataset size (like SVMs)

Disadvantages:  
Many classifiers  
More computation during prediction

------------------------------------------------------------  
WHICH STRATEGY IS BETTER

For SVMs, OvO is often faster and preferred.  
For most other algorithms, OvR is simpler and works well.

Scikit‑Learn automatically chooses:  
OvR for many models  
OvO for SVC

------------------------------------------------------------  
SCIKIT‑LEARN AUTOMATIC BEHAVIOR

If you use a binary‑only classifier (like SVC) on a multiclass dataset:  
Scikit‑Learn detects this  
It automatically applies OvR or OvO  
No manual coding is required

------------------------------------------------------------  
ERROR ANALYSIS 

Error analysis means examining the mistakes your model makes so you can understand why it is wrong and how to improve it. 
Instead of only looking at accuracy, you look at the specific errors the model produces. 
This helps you see which classes are confused, which samples are difficult, and what patterns the model fails to learn.

------------------------------------------------------------  
WHY USE A CONFUSION MATRIX

A confusion matrix shows all predictions compared to all true labels. For MNIST, it is a 10×10 grid.  
Rows represent actual digits.  
Columns represent predicted digits.

Each cell shows how many times the model predicted the column digit when the true digit was the row digit.  
If the cell at row 5, column 3 has a large value, the model often mistakes 5 for 3.  
This makes it easy to see which digits are confused.

------------------------------------------------------------  
WHY USE cross_val_predict

cross_val_score only gives accuracy.  
cross_val_predict gives actual predictions for every training sample using cross‑validation.  
This means each prediction is made on data the model did not train on.  
The confusion matrix built from these predictions shows true generalization errors, not training errors.

------------------------------------------------------------  
WHY THE CONFUSION MATRIX IS HARD TO READ

With 10 classes, the matrix contains 100 numbers.  
It is difficult to see patterns by looking at raw counts.  
A colored confusion matrix makes patterns visible.

------------------------------------------------------------  
WHY USE ConfusionMatrixDisplay.from_predictions

This function creates a heatmap.  
Dark colors indicate many errors.  
Light colors indicate few errors.

You can quickly see which digits are easy, which are hard, and where the model struggles.  
This visual representation makes error analysis much easier.

------------------------------------------------------------  
WHAT TO DO AFTER ERROR ANALYSIS

Once you know the mistakes, you can improve the model by:  
Adding more training samples for confusing digits  
Cleaning noisy or blurry images  
Using better preprocessing  
Trying a more powerful model  
Tuning hyperparameters  
Engineering better features

Error analysis tells you exactly where to focus your efforts.

------------------------------------------------------------  
SUMMARY

Error analysis means studying your model’s mistakes.  
Steps:  
Use cross_val_predict to get predictions  
Build a confusion matrix to see errors  
Plot a colored matrix to reveal patterns  
Improve the model based on what you learn
